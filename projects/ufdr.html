AI-UFDR
Forensic Intelligence Platform

An AI-based UFDR (Universal Forensic Extraction Device Report) analysis platform, split into two cooperating applications: SecureVault, the RBAC-governed, AES-256 encrypted evidence vault, and the Main Application, a natural-language query and intelligence layer built on top of it.

Built for the Smart India Hackathon 2025 forensic intelligence initiative for the National Investigation Agency, by Team Kaizen7.

Project Team: Kaizen7

Forensic Data Scientists & System Architects

System Overview

The platform is split into two independent applications. SecureVault is the encrypted evidence-vault module — it parses UFDR exports, extracts artifacts, encrypts them AES-256 at rest, and exposes them only through an RBAC-governed vault interface. The Main Application sits on top of it — a natural-language query engine and intelligence layer that queries the artifacts SecureVault has extracted and generates court-ready reports and cross-case analysis.

Application 1 — SecureVault

Encrypted Evidence Vault Module

Core Objectives

Normalized Extraction

Parses heterogeneous UFDR exports and extracts every artifact category — calls, messages, contacts, media, locations, app data — into a normalized JSON schema.

AES-256 Encryption at Rest

Every artifact is AES-256 encrypted before it is written to disk, with per-case key scoping so a compromised key can never expose the entire vault.

Role & Department RBAC

Investigators only ever see cases and artifacts within their assigned department and clearance, enforced at the service boundary, not just the controller.

Case-Scoped Vault Access

Retrieval is strictly case-scoped — an authorized investigator gets the artifacts they're cleared for, never a raw datastore dump.

End-to-End Auditability

Every upload, extraction, decrypt-on-read, and export is written to an append-only audit log for chain-of-custody compliance.

Legacy SOAP/XML Interop

Exposes a WSDL/SOAP contract alongside the primary REST/JSON API for department systems that cannot consume REST directly.

System Architecture

The module is layered so that parsing, extraction, security, and persistence remain independent, swappable concerns — consistent with the layered Spring Boot architecture used across the platform.

Security Design

Role-Based Access Control

Access is governed by a role × department matrix rather than a flat role list — Investigator, Forensic Analyst, Department Head, Administrator. A request is authorized only when the caller's role is permitted for that action and their department matches the case's owning department. Enforced with Spring Security method-level checks at the service boundary.

Encryption at Rest

Every artifact is AES-256 encrypted before it is written to the database, with keys scoped per case. TLS protects data in transit. Decryption happens only inside the Vault Access Layer, for a request that has already passed RBAC — nothing is decrypted speculatively or cached in plaintext.

Auditability

Every upload, extraction, decrypt-on-read, and export is written to an append-only audit log via a JMS queue, preserving chain-of-custody for evidence handled under NIA case procedures.

Data Flow

1. Upload & Auth

Investigator uploads a UFDR file through the console; the request passes the Spring Security filter chain (auth + RBAC check).

2. Parse & Extract

UFDRReader parses the file, then ArtifactExtractor pulls out each evidence category.

3. Validate & Encrypt

ValidationService checks structural integrity, then EncryptionService AES-256 encrypts each artifact before JPA/Hibernate persists it against the case record.

4. Serialize

ArtifactSerializer builds the JSON representation, with XML/XSLT export where required.

5. Vault Access

On access, VaultService re-checks RBAC for that case and decrypts only the requested artifacts — nothing is bulk-decrypted.

6. Audit

AuditLogService records the event asynchronously via JMS, regardless of outcome.

Database Design

PostgreSQL is the primary datastore for cases, artifacts, users, roles, departments, and the audit trail, accessed through JPA/Hibernate. Departments running on Oracle are served through a JDBC-based adapter so they can federate case metadata without migrating off their existing infrastructure.

Application 2 — Main Application

Natural-Language Query & Intelligence Platform

The Main Application ingests UFDRs, offers a natural language query interface, generates readable evidentiary reports, and runs a multi-stage AI pipeline — timeline reconstruction, cross-device correlation, behavioural pattern analysis, and risk scoring — on the artifacts that SecureVault has extracted and made available to it.

Main Application — System Architecture

React Frontend · Python Flask REST API · Gemini 2.5 Flash (Local) · PostgreSQL

Core Capabilities

UFDR Ingestion

Ingests UFDRs from industry-standard forensic tools (Cellebrite, Oxygen, MSAB) with automated validation, normalization, and artifact indexing.

Natural Language Query Interface

Investigators run complex cross-device searches in plain English — no SQL or manual filtering required.

Automated Report Generation

Generates court-ready reports, with summaries tailored to technical examiners or legal counsel.

Timeline Reconstruction & Correlation

Multi-stage AI pipeline linking activity across multiple seized devices, with behavioural anomaly detection and risk scoring for high-priority evidence.

AI Query Engine

The Investigative Query Assistant lets investigators query complex datasets in natural language. A locally deployed Gemini 2.5 Flash translates plain-English questions into precise, schema-aware SQL, keeping evidence discovery fast while preserving data sovereignty.

Automated Forensic Report Generator

The final integration layer between the relational database and the forensic document engine — it uses a stateful selection wrapper to transform queried data into a court-admissible format.

Reports export as PDF/A-3; the system generates a SHA-256 hash of the document and embeds a digital signature, providing non-repudiation and a verifiable chain of custody.

A YOLOv11 backbone handles real-time object detection; EasyOCR (ResNet-LSTM) handles alphanumeric extraction. Together they index unstructured visual evidence into a queryable relational database.
